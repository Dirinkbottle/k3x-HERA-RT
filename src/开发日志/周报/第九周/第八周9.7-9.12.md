# 第九周周报（9.7-9.12）

本周工作集中在 USB 设备自动匹配和 UVC 摄像头发现链路。USB host 在完成设备枚举、读取设备和配置描述符后，现在可以生成统一的 device/interface 描述对象，使用注册的 USB ID 表匹配驱动，并在 probe 成功后记录 interface 的逻辑认领状态。基于这条链路，为板上的 Suyin HD Camera 增加了一个名为 `uvcvideo` 的薄驱动，用于验证 UVC 设备的自动发现和匹配。

## 本周工作概览

- 在 `crab-usb` 中增加统一的 USB interface driver binding 机制。
- 将 VID/PID、interface class、subclass 和 protocol 封装为 `UsbId` 匹配规则，`None` 表示通配符。
- 增加 `UsbDevice`、`UsbInterface`、`UsbDriver`、`UsbIdEntry` 和 `UsbDriverRegistry`，串起枚举、匹配、probe、claim 和 disconnect 生命周期。
- 在 `ax-driver` 中增加 `uvcvideo` 薄驱动，精确匹配 `1e45:8022` 的 Video Control 和 Video Streaming interface。
- 调整 QEMU RISC-V 配置，保留 QEMU monitor socket，便于 USB 测试和调试。
- 在 K3 板上验证 Suyin HD Camera 的端口连接、USB enumeration、两个 Video interface 匹配和逻辑认领。

## USB 自动 probe 设计

USB host 端已经存在 xHCI 端口变化检测和设备枚举流程。本周没有改动 xHCI 的底层端口检测，而是把 driver binding 接到通用 `USBHost::probe_changes()` 入口，使 xHCI、DWC2、EHCI 和其他 host backend 可以复用同一套匹配逻辑。

当前调用链如下：

```text
xHCI 检测 port connect
        ↓
USB enumeration
        ↓
AddressDevice / GET_DESCRIPTOR / SET_CONFIGURATION
        ↓
生成 UsbDevice 和 UsbInterface
        ↓
遍历 USB driver registry
        ↓
UsbId::matches()
        ↓
UsbDriver::probe(interface)
        ↓
probe 成功后 interface 记录 driver
```

`UsbId` 只保留当前最需要的字段：VID、PID、interface class、subclass 和 protocol。设备级字段从父级 `UsbDevice` 读取，class 相关字段从 `UsbInterface` 读取。这样既可以表达 UVC 的 class 匹配，也可以表达 CH340 一类的 VID/PID 匹配。

`UsbDriverRegistry` 使用扁平的 `UsbIdEntry` 列表保存 ID 到 driver 的关系。匹配成功并不立即认领，必须先执行 `probe()`；如果 probe 返回错误，USB core 会继续尝试下一个匹配项。只有 probe 返回成功后，interface 才会记录绑定的 driver。设备断开时，host 根据设备逻辑 ID 找到已绑定的 interface，并调用 driver 的 disconnect 生命周期。

## `uvcvideo` 薄驱动

本周在 `ax-driver/src/usb/uvcvideo.rs` 中加入了用于验证发现链路的薄驱动，driver 名称为 `uvcvideo`，ID 表覆盖该设备的两个 Video interface：

```text
VID       = 0x1e45
PID       = 0x8022
Interface = 0x0e Video
Subclass  = 0x01 Video Control
Protocol  = wildcard
```

它在 USB host 创建时注册到 `USBHost`，因此首次拓扑扫描前就已经具备匹配规则。`probe()` 目前只输出设备 ID、interface 编号、alternate setting 和 endpoint 数量，然后完成逻辑 claim；它不会打开 live `Device`、不会直接 claim 底层 endpoint，也不会启动视频流。

现有 `drivers/usb/usb-device/uvc` 中的 `crab-uvc` 可以继续作为通用 UVC host-side 协议和视频流实现使用。它的 `UvcDevice::new()` 需要异步打开设备并取得独占 `Device`，同时要管理 Video Control 和 Video Streaming 两个 interface，因此不能直接塞入当前同步的 `UsbDriver::probe(&UsbInterface)` callback。后续需要单独设计 async probe、live device ownership、VC/VS 多 interface 管理、格式协商和 isochronous streaming 生命周期。
